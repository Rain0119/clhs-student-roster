# 學號查詢與名單轉換工具設計

日期：2026-11-12

## 專案邊界

本專案是獨立、公開的 GitHub 專案，讓使用者下載或 Fork 後，在本機轉換編班公告 PDF、替換內建名單，並以學號查詢學生資料。

班級投票與表單系統是另一個獨立的私人專案，預定放在相鄰的 `class-voting` 資料夾。兩者不共用 Git repository；本專案不包含 Google 登入、表單建立、選票、填答紀錄、Neon 憑證或私人網站程式。

本文件僅規範公開工具。私人系統另行撰寫設計與實作計畫。

## 已確認的目標與限制

- 公開工具與內建名單，供他人下載、修改與重建資料。
- 內建資料來自使用者提供的三份編班公告。
- 每筆學生資料只包含學號、姓名、班級、座號。
- 姓名依 PDF 擷取內容保留，包括遮蔽字元，不推測或補全姓名。
- 支援同格式、可擷取文字的 PDF；不承諾辨識掃描影像或任意學校格式。
- 工具在本機執行，不提供公開網站上傳 PDF 的功能。
- 不修改原始 PDF；不自動刪除使用者檔案。

## 第一版使用方式

第一版提供本機命令列工具與可重用的查詢、轉換模組，不另建網站介面。

使用者可選擇內建名單進行學號查詢；也可指定自己的 PDF 與來源格式，轉換後先檢視預覽和驗證報告，確認後再匯出 JSON、CSV。不得在預覽或驗證失敗時自動覆寫既有名單。若輸出路徑已有檔案，需明確選擇覆寫或改用新路徑。

工具不需 Google、Neon 或 Vercel 帳號即可執行。執行環境與安裝指令在實作計畫中選定，並由專案 README 清楚記載。

## 來源與轉換規則

| 原始來源 | 欄位處理 | 班級處理 |
| --- | --- | --- |
| `編班公告/115高一編班公告.pdf` | 讀取學號、姓名、班級、座號；排除報到序號 | 保留公告班級 |
| `編班公告/115高二編班公告.pdf` | 讀取學號、姓名、班級、座號；排除班群、數學等欄位 | 保留公告班級 |
| `編班公告/115高三編班公告.pdf` | 讀取學號、姓名、班級、座號；排除班群等欄位 | 2xx 轉為 3xx，例如 209 轉成 309；已為 3xx 的班級維持原值 |

來源格式必須明確選定，不依檔名自行猜測年級。處理其他同格式 PDF 時，也由使用者選擇來源格式及是否套用高三班級轉換。高三來源若出現 2xx、3xx 以外的班級，列為錯誤供人工檢查，不自動轉換。

目前原始 PDF 位於父資料夾的 `編班公告`，不移動或修改原檔。公開專案包含轉換後的四欄名單、來源對照說明與重建指令；原始 PDF 留在本機，不隨 repository 發布，以免一併公開不需要的其他欄位。他人可指定自己的本機 PDF 重建資料。

## 資料契約

JSON 輸出為學生物件陣列，CSV 使用相同的四個欄位，順序如下：

| 欄位 | JSON 型別 | 規則 |
| --- | --- | --- |
| `student_id` | 字串 | 學號；不以數值儲存，保留前導零 |
| `name` | 字串 | 原始遮蔽姓名；僅去除欄位外圍排版空白 |
| `class` | 字串 | 例如 `209`、`309`；套用指定來源轉換後的班級 |
| `seat` | 整數 | 正整數座號；`01` 與 `1` 統一為 1 |

JSON 使用 UTF-8；CSV 使用 UTF-8 BOM，方便 Windows 試算表軟體開啟。資料依班級、座號、學號排序；相同來源應產生相同順序與內容。

來源檔名、格式版本與轉換規則等資訊放在獨立的來源說明或驗證報告，不加進學生物件。一般查詢結果與正式名單不得帶出報到序號、班群、數學分組或其他額外欄位。

## 查詢行為

- 以完整學號精確查詢，回傳單筆四欄資料。
- 可接受完整的 `s學號@student.clhs.tyc.edu.tw` 作為查詢輸入，去除外圍空白後比對固定信箱格式，再擷取學號。
- 格式錯誤與學號不存在需分別顯示明確訊息，不以姓名模糊猜測身分。
- 輸入信箱只是查詢便利功能，不代表已驗證 Google 帳號或使用者身分；帳號驗證由私人系統處理。
- 支援依班級輸出名單；私人系統的初始名單選用高二來源的 209 班。

## 模組與資料流

來源 PDF → 依來源格式擷取 → 欄位正規化與班級轉換 → 驗證 → 預覽與報告 → 使用者確認匯出 → JSON／CSV。

工具分為來源擷取、正規化與驗證、匯出、學號查詢及命令列入口。來源格式的差異集中在擷取層；查詢和私人系統只依賴固定四欄契約。

私人投票系統在部署或管理員更新名單時，讀取 JSON 並匯入自己的 Neon。執行時不依賴公開專案的線上服務，也不從公開 repository 讀取實際填答或選票。

## 錯誤處理

- 缺少必要欄位、非正整數座號、非法學號或班級：報告來源檔、頁碼與原因，阻止正式匯出。
- 重複學號或同班同座號衝突：列出衝突，不覆蓋、不任選一筆。
- 空白頁、重複表頭、公告說明可排除；看似學生列卻無法解析的內容不得靜默略過。
- PDF 無文字、加密、損壞或格式不符：清楚說明無法處理，不產生看似完整的正式名單。
- 預覽顯示各來源與班級筆數、轉換規則及問題數，讓使用者在匯出前核對。

## 驗收標準

1. 三份內建 PDF 均可完整掃描，提供逐頁處理與總筆數報告；有問題的列必須可追查。
2. 人工對照各來源的第一頁、中間頁、最後一頁與 209 班，確認四欄對位及遮蔽姓名一致。
3. 高三來源的 2xx 均正確轉為 3xx；其他來源不受影響。
4. 正式 JSON／CSV 只含四個指定欄位，兩種輸出的筆數及內容一致。
5. 學號精確查詢、學校信箱查詢、未知學號及非法輸入行為符合規格。
6. 缺欄、重複學號、座號衝突、無文字 PDF 均明確失敗，不覆寫正式資料。
7. 他人依 README 可在不連接 Google、Neon、Vercel 的情況下，重建內建名單或轉換自己的同格式 PDF。
8. 公開專案不包含私人系統程式、授權憑證、填答紀錄或選票。

## 風險與最小驗證

最大風險是 PDF 看似成功擷取，但欄位錯位、漏列或來源班級被錯誤判讀。先以三份真實 PDF 的跨頁樣本與完整資料驗證處理核心，再建立完整查詢與匯出操作。單純成功輸出文字不算通過。

第二個風險是他人的 PDF 外觀相似、內部文字結構不同。第一版清楚界定支援格式，遇到不符格式即回報；後續新增來源解析器，不以寬鬆猜測換取表面成功。

## 設計自我檢查

本規格只涵蓋公開工具，與私人系統以四欄 JSON 契約銜接；未包含公開 PDF 上傳、Google 帳號驗證或投票功能。來源修正規則僅作用於明確選定的高三格式。所有失敗路徑均要求可追查及不覆寫，沒有未指定的自動資料修補行為。
